# Narration policy (restored October 25, 2026)

The user's preferred narration mode is Gemini TTS as primary, with Kokoro
fallback ONLY for individual segments that cannot be generated by Gemini,
then Edge as a last resort. Earlier episode-wide atomic fallback was rolled
back at the creator's request.

Audio generation runs Long + Shorts narration chunks together. Gemini
successes remain unchanged when a later segment fails. Transient Gemini
errors fall back for the affected segment; a confirmed daily quota/auth
failure blocks later Gemini attempts to avoid waste. The configured
per-run Gemini request cap remains in force.

out/voice_episode_report.json records each output filename and its actual
engine: gemini, kokoro, edge or indicf5. A mix is now permitted and disclosed.
A missing or silent narration chunk is a blocking error. The existing
Make storyboard/QC and review-only GitHub release behavior remain.

Pros: preserves good Gemini-voiced scenes, reduces unnecessary CPU
regeneration and returns to the creator's preferred behavior.
Cons: an episode may change vocal timbre at a fallback segment. This is
intentional and explicitly preferred over re-voicing the entire episode.

Offline test: python -m unittest discover -s tests -p 'test_episode_voice.py' -v

No Gemini, Canva or YouTube publishing API requests are made by these tests.
